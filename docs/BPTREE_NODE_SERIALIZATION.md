# BPTreeNode 序列化/反序列化实现说明

## 概述

实现了 BPTreeNode 的 `serialize()` 和 `deserialize()` 方法，用于将 B+ 树节点与磁盘页进行高效的相互转换。

## 序列化格式

采用**定长头部 + 变长数据**的设计，便于磁盘读取和随机访问。

### 格式定义

```
┌─────┬──────────┬──────────┬─────────────────────┐
│ [0] │ [1-4]    │ [5-8]    │ [9+]                │
├─────┼──────────┼──────────┼─────────────────────┤
│is_  │ key_     │ next_    │ 数据部分（变长）      │
│leaf │ count    │ leaf     │                     │
├─────┼──────────┼──────────┼─────────────────────┤
│1B   │ 4B(LE)   │ 4B(LE)   │ 变长                │
└─────┴──────────┴──────────┴─────────────────────┘
```

### 详细说明

| 位置 | 字段 | 大小 | 说明 |
|------|------|------|------|
| [0] | is_leaf | 1字节 | bool: 1表示叶子, 0表示内部 |
| [1-4] | key_count | 4字节(LE) | u32: 键的数量 |
| [5-8] | next_leaf | 4字节(LE) | u32: 下一个叶子页ID (0表示None) |
| [9+] | 数据部分 | 变长 | 见下表 |

### 叶子节点数据部分

对于每个键值对（共 key_count 条）：

```
┌──────────┬──────────┬──────────┬──────────┐
│ key_len  │ key_data │ page_id  │ slot_id  │
├──────────┼──────────┼──────────┼──────────┤
│ 2字节(LE)│ 可变长    │ 4字节(LE)│ 4字节(LE)│
└──────────┴──────────┴──────────┴──────────┘
```

- `key_len`: u16，键数据的字节长度
- `key_data`: 实际键数据
- `page_id`: u32，记录所在页号
- `slot_id`: u32，记录在页中的槽位（从u16转换）

### 内部节点数据部分

**第一部分**：所有键（共 key_count 条）

对于每个键：
```
┌──────────┬──────────┐
│ key_len  │ key_data │
├──────────┼──────────┤
│ 2字节(LE)│ 可变长    │
└──────────┴──────────┘
```

**第二部分**：所有子指针（共 key_count+1 条）

每个子指针：
```
┌──────────┐
│ child_id │
├──────────┤
│ 4字节(LE)│
└──────────┘
```

## 实现特性

### 优点

1. **定长头部** - 前8字节固定，便于快速判断节点类型和大小
2. **变长数据** - 支持任意长度的键值
3. **内存高效** - 使用 Vec 的 Write trait，避免过度分配
4. **错误处理** - 反序列化时完整的错误检查
5. **可扩展性** - 易于添加新的元数据字段

### 关键实现细节

- **字节序**: 采用 little-endian (LE) 编码，使用 `to_le_bytes()` 和 `from_le_bytes()`
- **Option 处理**: None 用 0 表示，Some(x) 用 x 表示
- **RID 存储**: page 是 u32，slot 是 u16，但存储时都转为 u32 (共8字节)
- **children 数量**: 内部节点有 key_count+1 个子指针

## 序列化大小

- **空节点**: 9 字节（仅头部）
- **单key叶子**: 9 + 2 + key_len + 8 = 19 + key_len
- **单key内部**: 9 + 2 + key_len + 4 + 4 = 19 + key_len

## 测试验证

通过以下测试场景验证实现正确性：

1. ✅ **叶子节点** - 包含多个 key 和 RID，支持 next_leaf
2. ✅ **内部节点** - 包含多个 key 和 children 指针
3. ✅ **空节点** - 无 key，仅头部数据
4. ✅ **单 key 节点** - 边界情况

## 使用示例

### 序列化

```rust
let mut node = BPTreeNode::new(1, true);
node.keys = vec![vec![1, 2], vec![3, 4, 5]];
node.rids = vec![(10, 1), (20, 2)];
node.next_leaf = Some(2);

let bytes = node.serialize();
// bytes 可以直接写入磁盘页
```

### 反序列化

```rust
let page_data = read_from_disk(); // 从磁盘读取页数据

match BPTreeNode::deserialize(&page_data) {
    Ok(mut node) => {
        node.page_id = page_id; // 恢复 page_id（从外部获取）
        // 使用 node
    }
    Err(e) => eprintln!("Deserialization error: {}", e),
}
```

## 注意事项

1. **page_id 处理** - 序列化不包含 page_id（它由页管理器维护），反序列化后需要手动设置
2. **次序一致性** - RID 和 children 的顺序必须与 keys 严格对应
3. **内存溢出** - 理论上可序列化的数据大小受单页大小限制（通常 4096 字节）
