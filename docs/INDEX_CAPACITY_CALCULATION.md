# B+ 树索引容量计算指南

## 1. 基本参数

### 系统配置
```
页面大小                  PAGE_SIZE = 4096 字节
树的阶数                  Order = 4
B+ 树节点头部大小         9 字节 (is_leaf=1 + key_count=4 + next_leaf=4)
记录ID大小               RID = 8 字节 (page_id=4 + slot_id=4)
```

## 2. 索引项大小计算

### 叶子节点中的索引项
```
索引项 = [key_len(2字节)] + [key(变长)] + [rid(8字节)]
                ↓                    ↓
          表示key的长度      page_id(4) + slot_id(4)
```

| 4字节  | 2      | 4      | 8    | 14   |
| 8字节  | 2      | 8      | 8    | 18   |

| 20字节 | 2      | 20     | 8    | 30   |
| 32字节 | 2      | 32     | 8    | 42   |

## 3. 每页能存放的索引项数

### 公式
```
可用空间 = 页面大小 - 节点头部
        = 4096 - 9
        = 4087 字节

每页容量 = ⌊ 可用空间 / 索引项大小 ⌋
        = ⌊ 4087 / 索引项大小 ⌋
```

## 4. 树的容量

### 树结构的递归关系

**假设**：
- Order = 4（最多 3 个键，4 个子指针）
- 所有节点都是满的

#### 单层树
```
根节点(叶子) = 3 个键 = 3 个索引项
容量 = 3 × (键大小为4时) = 3 项
```

#### 两层树
```
根节点(内部) = 3 个键，4 个子指针
└─ 4 个叶子节点，每个 3 个键

容量 = 4 × 3 = 12 项
```

#### 三层树
```
根节点(内部) = 3 个键，4 个子指针
├─ 4 个内部节点(第2层)，每个 3 个键，4 个子指针
│  └─ 16 个叶子节点(第3层)，每个 3 个键

容量 = 16 × 3 = 48 项
```

#### 四层树
```
容量 = 64 × 3 = 192 项
```

#### 五层树
```
容量 = 256 × 3 = 768 项
```

### 一般公式
```
N层树的容量 = 4^(N-1) × 3 个索引项

其中 4^(N-1) 是叶子节点数
```

## 5. 磁盘空间分配

### 页面对齐
```
任何B+树的大小都是 4096 字节的倍数

例如：
- 50 个索引项 → ~2 页 = 8 KB
- 100 个索引项 → ~4 页 = 16 KB
- 1000 个索引项 → ~40 页 = 160 KB
```

### 文件大小计算
```
所需页数 = ⌈ 总节点数 / (每页最大节点数) ⌉

例子（键大小 4 字节，每页 291 项）：
- 300 项 → ⌈ 300 / 291 ⌉ = 2 页 = 8 KB
- 600 项 → ⌈ 600 / 291 ⌉ = 3 页 = 12 KB
- 1000 项 → ⌈ 1000 / 291 ⌉ = 4 页 = 16 KB
```

## 7. 优化建议

### 针对小数据集
```
如果索引项 < 300：
├─ 使用单页 B+ 树（叶子是根节点）
├─ 无需树结构开销
└─ 直接线性查询即可
```

### 针对大数据集
```
如果索引项 > 10,000,000：
├─ 考虑使用更大的 Order（8, 16 等）
├─ 减少树高度
├─ 改进缓存局部性
└─ 使用批量插入优化
```

### 针对特定键类型
```
小键 (< 4字节)    → Order=4, 每页 340+ 项
标准键 (4-8字节)  → Order=4, 每页 227-291 项
大键 (> 20字节)   → Order=8, 每页 150+ 项
```

## 8. 内部节点容量

### 内部节点结构
```
内部节点 = [key_len + key] × key_count + [child_page_id] × (key_count + 1)

对于 4 字节键的内部节点：
每条记录 = 2 + 4 + 4 = 10 字节（key + child指针分摊）

每页容量 ≈ 4087 / 10 ≈ 408 条条目（实际取决于实现）
```

### 内部节点效率
```
Order = 4 时：
├─ 每个内部节点有 3 个键和 4 个子指针
├─ 大部分内部节点不会满
└─ 存储效率相对较低（设计特性）
```

## 9. 性能特征

### 搜索性能
```
键查询：O(log₄ N)

例子：
├─ 100 项 → log₄(100) ≈ 3.3 ≈ 4 次比较
├─ 1000 项 → log₄(1000) ≈ 5 次比较
└─ 1000000 项 → log₄(1000000) ≈ 10 次比较
```

### 范围扫描
```
范围查询：O(log₄ N + K)

其中：
├─ N = 树中索引项总数
├─ K = 结果集大小
└─ log₄ N 用于找到范围起点
    K 用于遍历叶子链

例子（N=100, K=10）：
├─ 找到起点：4 次比较
└─ 遍历链：10 次页访问
总计：14 次页访问
```

### 分裂成本
```
分裂操作：O(M) 其中 M = Order

每次分裂涉及：
├─ 遍历：O(log N)
├─ 重新组织：O(M) = O(4)
├─ 写入：O(2 页)
└─ 总成本：O(log N) 分摊每次插入

N 次插入的总成本 = O(N log N)
```

## 10. 页面格式示例（键大小 4 字节）

### FileHeader 页（Page 0）
```
字节偏移  内容         大小
────────────────────────
0        header_size  4    → 0x0c = 12
4        total_pages  4    → 0x01 = 1 (initially)
8        free_list    4    → 0x00 = 0 (empty)
12       [padding]    4084 → 0x00 (zeros)
──────────────────────────
总计     4096 字节
```

### 叶子节点页示例（Page 1+）
```
字节偏移  内容               大小
─────────────────────────────────
0        is_leaf            1    → 0x01 = true
1        key_count          4    → 0x32 = 50 (example)
5        next_leaf          4    → 0x02 = page 2 (if exists)
9        key_len[0]         2    → 0x04 = 4
11       key[0]             4    → [索引键 1]
15       rid[0].page        4    → [页ID]
19       rid[0].slot        4    → [槽ID]
23       key_len[1]         2    → 0x04 = 4
...      ...                ...  → [更多条目]
        [数据直到 4087]
4087     [对齐填充]    到 4096
─────────────────────────────────
总计     4096 字节
```
